Erros encontrados: 
O SQL esta montado com template string, porém a regra do projeto exige consultas parametrizadas com ?
O SQL esta sendo executado dentro de rotas, mas ele deveria ficar isolado em models.
Falta de return após o envio da mensagem de erro, onde ele tenta enviar duas respostas para a mesma requisição

Correção do código:
// models/FonteDestino.js
static async excluir(id, usuarioId) {
  const [r] = await db.query(
    'DELETE FROM fontes_destinos WHERE id = ? AND usuario_id = ?',
    [id, usuarioId]
  );
  return r.affectedRows > 0;
}

// routes/fontesDestinos.js
router.delete('/:id', async (req, res) => {
  const excluiu = await FonteDestino.excluir(req.params.id, req.auth.id);

    return res.status(404).json({ erro: 'Fonte/destino não encontrada.' });
  }
  res.status(204).end();
});

Treino 6. Explique, em até 4 linhas, por que UNIQUEno banco é necessário mesmo que a rota faça um SELECTantes de inserir.
Se a aplicação depender apenas de um SELECT antes do INSERT, duas requisições simultâneas podem realizar a busca no mesmo milissegundo, não encontrar o registro e prosseguir com a inserção simultaneamente, resultando em duplicidade (condição de corrida). A restrição UNIQUE garante que o próprio banco de dados bloqueie a segunda inserção concorrente (disparando o erro ER_DUP_ENTRY), o qual a API captura e converte de forma segura em um erro HTTP 409.
